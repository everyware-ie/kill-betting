새 기능 시작을 위한 진입점. 요구사항 정의와 설계를 한 세션에 완료하고, 다음 단계로 넘어갈 명확한 요약을 제공한다.

**언제 사용:** 구현 시작 전 항상. 이 과정 없이 코딩을 시작하지 않는다.

## 진행 순서

### 1단계 — 요구사항 정의 (그릴링)

`/grilling` 세션을 실행한다. 아래 항목이 모두 해소될 때까지 계속한다:

- 이 기능이 해결하는 문제는 무엇이고, 누구에게 영향을 미치는가?
- "완료"란 어떤 상태인가? (추상적 목표가 아닌 구체적인 동작으로)
- 이번 범위에서 명시적으로 제외하는 것은 무엇인가?
- 설계를 바꿀 수 있는 엣지 케이스가 있는가?
- 이 기능을 담당하는 팀원은 누구인가?

모든 결정 분기가 해소되기 전에 2단계로 넘어가지 않는다.

### 2단계 — 설계 및 도메인 모델링

`/domain-modeling`을 실행한다. 아래 항목을 함께 정리한다:

- 수정되는 모듈은 무엇인가?
- 인터페이스 변경 사항은 무엇인가? (입력, 출력, 사이드이펙트)
- 테스트 경계(seam)는 어디인가?
- `CONTEXT.md`에 추가해야 할 용어가 있는가?
- 이 결정을 ADR로 남겨야 하는가?

머지 충돌 위험도 확인: 다른 팀원이 같은 파일을 수정하고 있을 가능성이 있는가? 있다면 진행 전에 사용자에게 알린다.

### 3단계 — 세션 요약 및 다음 단계 안내

아래 형식으로 세션을 정리하고 사용자에게 확인을 받은 후 종료한다:

```
기능명: [이름]
담당자: [팀원]
문제: [한 문장]
완료 기준: [구체적인 조건]
수정 모듈: [목록]
충돌 위험: [충돌 가능성 있는 파일, 또는 "없음"]

다음 단계:
1. /to-prd     — 이 세션 내용을 PRD로 정리
2. /to-issues  — PRD를 구현 가능한 이슈로 분해
3. tdd         — 이슈 단위로 구현
```
