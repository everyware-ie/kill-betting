## 1. Overview

- 사용자가 OCR로 파싱된 매치 결과를 검토하고, **확정(confirm) API 한 번으로 검토 승인과 세션 반영을 동시에 처리**한다.
- "확정"이란 OCR 결과를 사용자가 맞다고 인정하는 행위이며, 이 시점에 팀 점수 및 랭킹 계산도 함께 이루어진다.
- 별도의 "검토 완료" → "반영" 2단계 흐름은 없다. confirm API가 두 역할을 모두 담당한다.

---

## 2. Roles & Permissions

### 2.1 역할 정의

- **Uploader (업로드 담당자)**
  - 팀 매치 결과 확정 가능
- **Team Member (일반 팀원)**
  - 확정 불가 (조회만 가능)

### 2.2 권한 정책

- 확정은 Uploader 역할을 가진 사용자만 가능
- 한 팀당 업로드 담당자는 1명

---

## 3. User Flow

1. 사용자가 매치 결과(팀 기준) 이미지를 업로드
2. OCR로 파싱된 결과 확인 및 수정
3. **"확정(confirm)" 요청 → 검토 승인 + 세션 반영 동시 처리** (`PENDING` → `CONFIRMED`)
4. 팀 랭킹 및 점수 업데이트

> ⚠️ 이전 설계의 "검토 완료(confirmed) 상태 변경" → "세션 반영" 2단계 흐름은 제거되었다.
> confirm API 단일 호출로 처리된다.

---

## 4. Functional Requirements

### 4.1 조건

- 매치 상태가 `PENDING`이어야 한다 (이미 `CONFIRMED`인 매치는 재확정 불가)
- 해당 매치가 특정 킬내기 세션에 연결되어 있어야 한다
- 팀 단위 결과 데이터가 존재해야 한다
- Uploader 권한을 가진 사용자가 요청해야 한다

---

### 4.2 데이터

- 팀 ID
- 팀 총 킬 수
- 팀 순위
- 팀 생존 시간
- 개인별 딜량, 킬수
- 치킨 여부

### ✔️ 점수 계산 예시

- 점수 = (팀 킬 수 × k) + 순위 보너스

---

### 4.3 결과

- 팀 점수 업데이트
- 세션 내 팀 랭킹 재정렬
- 해당 매치 상태가 `CONFIRMED`로 변경됨

---

## 5. Acceptance Criteria

- [ ]  `PENDING` 상태의 매치만 확정할 수 있다
- [ ]  확정 API 한 번으로 OCR 결과 승인과 세션 반영이 동시에 처리된다
- [ ]  팀 단위 결과가 세션 점수에 반영된다
- [ ]  동일 매치는 한 세션에 1회만 반영된다 (`CONFIRMED` 상태 중복 요청 거부)
- [ ]  확정 후 팀 랭킹이 즉시 업데이트된다
- [ ]  확정 결과가 UI에 반영된다
- [ ]  확정 실패 시 에러 메시지가 표시된다
- [ ]  Uploader만 확정 요청을 할 수 있다
- [ ]  권한 없는 사용자가 확정 시도 시 요청이 거부된다
- [ ]  권한 오류 시 적절한 에러 메시지가 반환된다

---

## 6. Edge Cases

- 팀 구성원이 일부만 세션에 참여한 경우
- 매치에는 팀이 있지만 세션에는 개인만 존재하는 경우
- 세션 종료 이후 확정 시도
- 팀 ID 불일치 / 매핑 실패
- Uploader가 아닌 사용자가 확정 시도하는 경우

---

## 7. Non-functional Requirements

- 데이터 정합성 보장 (트랜잭션 처리)
- 중복 확정 방지 (idempotency key: matchId)
- 확정 처리 시간 1초 이내

---

## 8. Out of Scope

- 팀 구성 변경
- 점수 계산 방식 변경 UI
- 매치 데이터 자동 분석 (OCR 등)
