## 1. Overview

- 하나의 세션에는 여러 팀이 참여하여 대결한다
- 각 팀은 최대 4명의 플레이어로 구성된다
- 각 팀에는 **업로드 담당자 1명**이 존재하며, 반드시 서비스 회원이어야 한다
- 업로드 담당자를 제외한 팀원은 비회원도 참여 가능하며 닉네임으로 식별된다
- 세션 및 팀 구성 과정은 **실시간으로 동기화**된다
- 사용자는 팀 구성 상태 및 변경 사항을 **실시간으로 확인할 수 있다**

---

## 2. Roles & Definitions

### 2.1 역할 정의

- **Host (방장, 세션당 1명)**
  - 세션 생성
  - 팀 생성
  - 업로드 담당자 지정
- **Uploader (팀별 담당자, 팀당 1명)**
  - 팀원 정보 입력 및 수정
  - 매치 결과 업로드
- **Team Member (팀원)**
  - 실제 게임 참여자
  - 비회원 가능 (닉네임 기반)

---

## 3. User Flow

1. Host가 세션 생성
2. 팀 생성 (N개 팀)
3. Host가 각 팀별 업로드 담당자 지정
4. 각 업로드 담당자가 팀원 닉네임 입력
5. 모든 참여자는 팀 구성 상태를 실시간으로 확인
6. 세션 준비 완료

---

## 4. Functional Requirements

### 4.1 세션 구성

- 세션은 2개 이상의 팀을 포함해야 한다
- 각 팀은 최대 4명의 플레이어로 구성된다

---

### 4.2 업로드 담당자

- 각 팀에는 정확히 1명의 업로드 담당자가 존재해야 한다
- 업로드 담당자는 반드시 서비스 회원이어야 한다
- 업로드 담당자는 Host가 지정한다

---

### 4.3 팀원 관리

- 팀원은 닉네임 기반으로 입력된다
- 팀원은 서비스 회원이 아닐 수 있다
- 팀원 수는 최대 4명 (팀별 업로드 담당자 포함)
- 팀별 인원은 최소 1명이며, 팀마다 참여 인원이 다를 수 있다.

---

### 4.4 입력 데이터

### Team

- teamId
- uploaderUserId
- members[]

### TeamMember

- memberId
- playerNickname
- createdByUserId
- updatedByUserId
- createdAt
- updatedAt

---

### 4.5 WebSocket 기반 실시간 상태 동기화

- 클라이언트는 세션 입장 시 WebSocket에 연결한다
- 서버는 세션 단위 채널(room)을 관리한다
- 동일 세션 참여자는 동일 채널을 구독한다
- 모든 상태 변경은 이벤트로 broadcast 된다

---

### 4.6 상태 모델

각 팀은 다음 상태를 가진다:

- EMPTY (팀원 없음)
- EDITING (입력 진행 중)
- READY (최소 조건 충족)
- COMPLETED (입력 완료)

---

## 5. Acceptance Criteria

- [ ]  세션에는 여러 팀이 생성될 수 있다
- [ ]  각 팀은 최대 4명으로 구성된다
- [ ]  각 팀에는 반드시 1명의 업로드 담당자가 존재한다
- [ ]  업로드 담당자는 서비스 회원이어야 한다
- [ ]  팀원은 비회원도 입력 가능하다
- [ ]  업로드 담당자가 팀원 정보를 입력할 수 있다

### 실시간 관련

- [ ]  모든 변경 사항은 1초 이내에 모든 사용자에게 반영된다
- [ ]  팀원 추가/수정/삭제 시 실시간 동기화된다
- [ ]  누가 입력했는지(actorUserId)를 확인할 수 있다
- [ ]  업로드 담당자의 접속 상태를 확인할 수 있다
- [ ]  동일 세션 내 다른 팀 상태도 실시간으로 확인 가능하다

---

## 6. Edge Cases 🔥

- 팀원 4명 초과 입력 시도
- 업로드 담당자가 없는 팀 생성
- 동일 사용자가 여러 팀 담당자로 지정
- 동일 닉네임 중복 입력
- 비회원 닉네임 변경/추적 불가
- 업로드 담당자가 존재하지 않는 사용자
- 동시 수정 충돌 (race condition)
- 네트워크 끊김 중 입력
- 이벤트 유실 또는 지연

---

## 7. 충돌 핸들링

- 서버 authoritative 방식 사용
- 모든 변경은 서버에서 최종 결정

### 방식

- 낙관적 UI 적용 가능
- 충돌 발생 시 서버 상태로 롤백

---

## 8. Non-functional Requirements

- 실시간 반영 지연: 1초 이하
- 서버 기준 데이터 정합성 유지
- WebSocket 기반 통신 사용
- 높은 동시성 환경에서도 일관성 유지

---

## 9. Out of Scope

- 팀 자동 매칭
- 닉네임 검증 (PUBG API 연동)
- 계정 연동 기능
