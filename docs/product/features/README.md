# product/features — 구현 노트

기능정의(FRD)의 **원문은 이 레포의 [`docs/specs/frd/`](../../specs/frd/)** 에 있다.
이 폴더는 기능별 **구현 노트 1개씩**: FRD 링크 + 구현 상태 + 코드 구조·기술적 선택 메모를 담는다. **규칙 원문은 복사하지 않는다** (이중 관리 → 어긋남의 근원).

> **2026-08-03 변경**: FRD 원문이 허브(mechuri-docs)에서 이 레포로 이관됐다. 이전에는 이 폴더가 "허브 FRD 스텁"이었고 링크가 교차 repo 절대 URL이었는데, 그 링크 4건이 전부 조용히 깨져 있었다(파일명 불일치 2건·링크 누락 2건). 이제 FRD가 같은 레포에 있으므로 **상대경로**로 연결한다. 배경: [2026-08-03 결정](https://github.com/everyware-ie/mechuri-docs/blob/main/team/decisions/2026-08-03-ideation-pipeline-location.md)

## 구현 노트 템플릿

```markdown
# <기능 이름>

- FRD: ../../specs/frd/<파일>.md
- 이슈: #N, #N
- 구현 상태: 진행 중 | 완료 (<PR 링크>)

## 구현 노트
<코드 구조, 기술적 선택, FRD와의 매핑 등 — 구현자가 자유롭게>

## 어긋남 기록
<FRD와 불일치 발견 시: 날짜, 내용, 이슈 링크>
```

## 규칙

1. **FRD가 상류**: 구현 노트와 FRD가 어긋나면 FRD가 우선. 다만 이제 같은 레포·같은 PR에서 함께 고칠 수 있으므로, 발견 즉시 **FRD도 같은 PR에서 갱신**하는 것을 기본으로 한다.
2. **approved만 구현**: FRD의 status가 `approved`가 아니면 착수하지 않는다.
3. FRD를 개정했다면 관련 구현 노트의 영향도 같은 PR에서 확인한다.
4. PRD(제품 요구 문서)는 `docs/specs/prd/`에 둔다 — 이 폴더가 아니다.
