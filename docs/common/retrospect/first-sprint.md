# 1회차 회고

프로덕트 MVP 개발을 마치고, 팀원들과 함께 첫 번째 스프린트에 대한 회고를 진행했습니다. 각자 느낀 점과 개선할 점을 공유하며, 앞으로의 개발 방향에 대해 논의했습니다.

## 🟢지응

### Keep
- 빠른 개발 템포로 일단 치고 나가고 개발 바로바로 해 나가는게 좋았다
- 사용자 중심으로 기획을 고민하고 서로 할 말을 다 하는 분위기가 좋았다

### Problem
- 사용자 경험을 깊이 고민하는 것 좋았지만 기획 논의가 너무 늘어지는 경향이 있었다
- AI를 많이 활용하다보니 다른 사람들의 파트와 겹쳐 충돌이 자주 일어났다

### Try
- 기획 제한시간 설정 (특정 주제 논의 최대 15분 등)
- 일단 만들고 검증 → 확신이 없어도 프로토타입 먼저하고 피드백은 써보면서 하는 느낌 (우리가 그 누구보다 많이 사용해보는 느낌으로)
- 가이드를 좀 더 정해놓으면 좋을 것 같다 (충돌 대비)


## 🟡지민

### Keep
- 의견을 바로바로 자유롭게 이야기하는 게 제일 중요하다고 생각하는데 그런 환경이라 좋았다.
- AI를 적극적으로 활용하여 빠르게 다양한 시도를 한 것들이 좋았다.
- 모두 다 각자의 분야에만 매몰되지 않고 필요한 포지션에 맞춰 개발 or 기획하는 것이 좋았다~

### Problem
- 팀 단위 결정은 1주일에 2시간 정도이다 보니? 아니면 MVP가 컸던 건지? 개발이 확정되는 구현까지 걸리는 시간은 빨랐지만, 사용자에게 배포되기까지는 시간이 걸렸다.
- AI 스킬이 공통화되지 않은 부분들이 있어, 일부분 비효율적이게 돌아간 부분들도 있는 것 같다.
- 가이드나 기능 정의가 빠진 부분들이 있어서 재논의하기도 했었다.

### Try
- MVP를 더 작게, UT를 더 자주 빠르게 시도해보면 좋을 것 같다.
- 초반에 AI 스킬이나 가드레일을 더 탄탄하게 해두는 것이 장기적으로 서비스를 유지하는 것에 좋을 것 같다. 팀 문서화도 잘 해두면 유지보수에 더 수월할듯.

## 현수

### Keep
- AI 적극 활용 
- 빠른 시도
- 편안한 의사소통 (카메라 켜기)
- 그때그때 필요할 때 모인 거

### Problem
- 맡은 파트가 명확하지 않아서 AI 활용 시 중복됐던 것들..?
- 프론트 코드 작업할 때 테스트를 할 때 DB 구조를 모르다 보니 제대로 되는 게 맞는지에 대한 의문?
- 중간 요구사항 변경에 대한 관리

### Try
- 다음엔 AI를 활용해서 더 빠른 속도를 낼 수 있도록 초반에 AI를 활용해서 개발하기 쉬운 기초 세팅을 해두고 시작하면 좋겠다..?
  예를 들면) 초반에 Entity 설계, API, 어떤 기술을 쓸지..? 어떤 tree 구조로 도메인을 구현할지..?
- 중간 요구사항 변경에 대해서 좀 더 체계적으로 빠르게? 반영해서 모두가 같은 내용을 인지할 수 있는 방법이 있으면 좋겠다
